# Attacks on the sheaf explanation

Run these against `docs/SHEAF.md` after every rewrite.
If a sentence can be read as one of the easy readings below, the sentence is wrong.

| Id | Attack | Required refusal |
|---|---|---|
| E1 | “So it’s a knowledge graph.” | Graphs relate entities. Sheaves assign data and compare through a specified map. |
| E2 | “So it’s embeddings / similarity.” | Near vectors can fail a named-field comparison. `"1"` vs `1` is exact. |
| E3 | “So it’s just a type system.” | Types check one file. The sheaf checks the overlap. |
| E4 | “So it’s the write-gate.” | Building the sheaf does not refuse writes. |
| E5 | First paragraph unreadable | Lead with local truths / overlap / one picture. No Φ, ρ, H¹. |
| E6 | So simple it does not constrain behavior | Keep: no locator → not a part; no evidence → not an overlap. |
| E7 | Atlas hides different record shapes | Parts may carry different fields; compare only what the overlap names. |
| E8 | “Lattice = sheaf.” | Lattice is a drawing. |
| E9 | “Everything is a sheaf.” | Empty shared fields / no observed overlaps fail. |
| E10 | Jargon leak | No coboundary, site, descent, presheaf, cohomology on SHEAF.md except the last table. |

Lesson: a sheaf is local data plus comparison-on-overlaps. The lattice is a picture. The package is the repeatable rule. The write-gate is a use. If an explanation collapses those four into one word, it is reductionist.
